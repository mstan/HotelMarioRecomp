# Validation limits

Hotel Mario is a research preview. Earlier input-driven checks cleared Hotel 1 Stages 1-3; a separate two-player build reached partial early-game checkpoints. Published v0.0.3 selected native jobs were qualified against the LLE reference in a bounded workload through field 13,000. These observations do not certify a complete campaign.

Open acceptance includes every hotel/boss/ending, both complete player modes, correct active-stage restoration from original in-game saves, sustained windowed reliability and audio listening quality. Keep these gaps explicit when shipping previews.

The launcher integration and repository cleanup preserve that acceptance boundary. Component checks, fresh builds, package audits and bounded runtime checks establish the changed build/product path; they do not turn earlier partial results into full-playthrough certification.

Run game checks using the TCP/debug interface with known explicit BIOS/disc paths and an isolated profile. Avoid speaker output in unattended tests. Retain exact build/settings identities, captures and individual observations privately in central tracking.
